# AR: การกำเนิดของระบบสุริยะ

## ต้องอัปโหลดครบ 4 ไฟล์นี้ ไว้โฟลเดอร์เดียวกัน

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `index.html` | หน้า AR ทั้งหมด |
| `marker.patt` | marker แบบดวงอาทิตย์ที่ทำให้ตอนแรก |
| `pattern-hiro.patt` | marker Hiro มาตรฐาน |
| `camera_para.dat` | ค่าพารามิเตอร์กล้องของ ARToolKit ถ้าขาด = ตัวจับ marker ไม่เริ่มทำงาน |

หน้านี้รับ marker ได้ทั้งสองแบบ เจออันไหนก่อนก็ใช้อันนั้น พิมพ์จาก `marker-hiro.pdf` หรือ `marker.pdf` (A4 ได้ขนาดราว 10 × 10 ซม.)

## บั๊กตัวจริงที่ทำให้ภาพไม่ขึ้น: `smooth="true"`

AR.js 3.4.5 ใน `arjs-markercontrols.js` เวลาเปิด smooth จะเทียบค่าเมทริกซ์ปัจจุบันกับค่าเฉลี่ยย้อนหลัง ถ้าต่างกันไม่ถึง `smoothThreshold` มันจะ **ไม่ก็อปเมทริกซ์ลง object3D เลย** ด้วยเหตุผลว่าจะลด jitter ผลคือถ้าถือกล้องนิ่ง ๆ เมทริกซ์จะค้างเป็น identity ตั้งแต่เฟรมแรก โมเดลเลยไปกองอยู่ที่ตำแหน่งกล้องพอดีและมองไม่เห็น ทั้งที่ `markerFound` ยิงออกมาแล้ว (ป้ายบอกให้ส่อง marker จึงหายไป)

ตอนนี้ถอด `smooth` ออกหมดแล้ว และเขียนการหน่วงการสั่นเองด้วย `lerp`/`slerp` ในโค้ดเราแทน ห้ามใส่ `smooth="true"` กลับเข้าไปในแท็ก `<a-marker>`

## ที่แก้ในเวอร์ชันนี้

1. **จอมืด** — AR.js วางวิดีโอกล้องไว้ที่ `z-index:-2` ซึ่งจะถูกพื้นหลังของ `body` วาดทับเสมอ แก้ด้วยการย้ายสีพื้นไปไว้ที่ `<html>` และให้ `body` โปร่งใส **ไม่แตะ z-index ของวิดีโอหรือ canvas** เพราะถ้ายกวิดีโอขึ้นมาเหนือ canvas วิดีโอจะบังภาพ 3D ทั้งหมด
2. **ปุ่มความเร็วกับแถบขั้นตอนไม่ขึ้น** — เดิมสร้างจากในคอมโพเนนต์ 3D ถ้าคอมโพเนนต์ไม่เริ่มทำงาน ปุ่มก็หายไปด้วย ตอนนี้ HUD สร้างแยกและกดได้ตลอด
3. คอมโพเนนต์ 3D ลงทะเบียนก่อน `<a-scene>` และไม่ได้แขวนใต้ `<a-marker>` แล้ว จึงไม่พังตามถ้า `marker.patt` โหลดไม่ได้
4. `camera_para.dat` ย้ายมาโหลดจากโฟลเดอร์เดียวกัน ไม่ต้องพึ่ง CDN ภายนอกที่บางทีช้าหรือโดนบล็อก
5. ถอด `precision: mediump` กับ `logarithmicDepthBuffer` ออกจาก renderer สองตัวนี้ทำให้ภาพ 3D หลุดออกนอกจอหรือถูก clip ได้บน iOS เพราะ AR.js กำหนด projection matrix เอง
6. เปลี่ยนมายึดโมเดลกับ marker ด้วยการก็อปตำแหน่งเองทุกเฟรม แทนการฝากเป็นลูกของ object3D ของ AR.js
7. เพิ่มกรอบเรืองแสงรอบ marker กับจุดสีฟ้าตรงกลาง เห็นทันทีว่าจับ marker ติดแล้วและวาดภาพได้
8. แก้ชื่อ attribute ของ marker ให้เป็น kebab-case (`smooth-count`) ของเดิมเขียนแบบ camelCase ซึ่ง AR.js ไม่รับค่า
9. เพิ่มแผงแจ้งปัญหา ถ้าผ่านไป 9 วินาทีแล้วยังไม่มีภาพ จะบอกว่าติดขั้นไหน (ไลบรารี / WebGL / กล้อง / ไฟล์หาย) พร้อมปุ่มโหลดใหม่กับปุ่มดูแบบไม่ใช้กล้อง

## เปิด test.html ก่อนเป็นอย่างแรก

`test.html` คือตัวอย่างมาตรฐานของ AR.js เปล่า ๆ ไม่มีโค้ดที่เราเขียนอยู่ในนั้นเลย มีแค่ลูกบาศก์แดง (marker Hiro) กับลูกบอลเหลือง (marker ดวงอาทิตย์) ต้องอัปโหลดไปพร้อมกับ `pattern-hiro.patt`, `marker.patt`, `camera_para.dat`

- **เห็นลูกบาศก์แดง** = เครื่อง เบราว์เซอร์ กล้อง marker และ AR.js ทำงานครบ ปัญหาอยู่ในหน้า index.html ของเรา
- **ไม่เห็นเลยทั้งที่ภาพกล้องขึ้น** = ตัว AR.js เองแสดงผลบนเครื่องนี้ไม่ได้ ไม่ใช่เรื่องโค้ดเรา ให้ลองเปลี่ยนเบราว์เซอร์หรือเปลี่ยนเครื่องทดสอบ

## ลูกบาศก์ฟ้า-ส้มกลางจอคือจุดทดสอบ

เวอร์ชันนี้มีลูกบาศก์เล็ก ๆ หมุนอยู่กลางจอค่อนไปทางล่าง มันยึดกับกล้อง ไม่เกี่ยวกับ marker เลย ใช้แยกปัญหาสองอย่างที่คนละเรื่องกันออกจากกัน

- **เห็นลูกบาศก์** = WebGL แสดงผลบนจอได้ปกติ ปัญหาเหลือแค่การจับ marker
- **ไม่เห็นลูกบาศก์** = WebGL ไม่ได้แสดงผลบนจอเลย เป็นเรื่องการซ้อนชั้นของ canvas ไม่ใช่เรื่อง marker

พอมั่นใจว่าใช้งานได้แล้ว ลบแท็ก `<a-entity id="check" ...>` ออกจาก `index.html` เพื่อเอาลูกบาศก์นี้ออก

หน้านี้จะสรุปผลให้เองที่วินาทีที่ 12 ด้วย ถ้ามีอะไรผิดปกติจะขึ้นแผงบอกว่าติดขั้นไหนพร้อมตัวเลขประกอบ

## ถ้ายังไม่เห็นโมเดล

ต่อท้าย url ด้วย `?debug=1` จะเปิดหน้าต่างภาพขาวดำที่ AR.js ใช้หา marker พร้อมเปิดแผงตัวเลขให้เลย ถ้าในภาพขาวดำนั้นกรอบ marker ไม่เป็นสี่เหลี่ยมดำทึบชัด ๆ แปลว่าแสงหรือระยะยังไม่พอ

หรือกดปุ่ม `i` มุมขวาของการ์ดขั้นตอน

จะมีตัวเลขสถานะขึ้นมา อ่านได้แบบนี้

- `draw calls` เป็น 0 ตลอด = ตัววาดภาพไม่ทำงาน (ปัญหา WebGL)
- `marker visible=false` ตลอดขณะส่องอยู่ = จับ marker ไม่ได้ (แสง เงา หรือกรอบขาวรอบ marker ไม่พอ)
- `model visible=true` พร้อม `pose` มีตัวเลขเปลี่ยนไปมา แต่จอยังว่าง = โมเดลถูกวาดแต่ถูกอะไรทับอยู่
- `video z=` ควรได้ 0 และ `canvas z=` ควรได้ 1

ถ้ากด "ดูแบบไม่ใช้ marker" แล้วเห็นโมเดล แต่ส่อง marker ไม่เห็น แปลว่าเป็นเรื่องการจับ marker ไม่ใช่เรื่องการวาดภาพ

## เปิดใช้งาน

ต้องเปิดผ่าน **https** หรือ **localhost** เท่านั้น กล้องจึงจะทำงาน และควรเปิดใน Safari หรือ Chrome โดยตรง เบราว์เซอร์ในแอป LINE / Facebook มักไม่อนุญาตให้ใช้กล้อง (หน้านี้ตรวจเจอแล้วจะเตือนให้)

```bash
python3 -m http.server 8000    # แล้วเปิด http://localhost:8000
```

## สองโหมด

แท็บมุมซ้ายบนสลับได้สองโหมด

**กำเนิดระบบสุริยะ** — ไทม์ไลน์ 6 ขั้นแบบเดิม เนบิวลาจนถึงระบบสุริยะปัจจุบัน ปรับความเร็วได้ ข้ามขั้นได้

**ดาวเคราะห์** — เลื่อนแถบด้านล่างเพื่อเลือกดาว ดาวที่อยู่กลางจอคือดาวที่เลือก แตะที่ชื่อก็ได้ ดาวจะขึ้นบน marker หมุนรอบแกนของตัวเองที่เอียงตามค่าจริง (ยูเรนัส 97.8 องศา ศุกร์หมุนสวนทาง) พร้อมการ์ดคำอธิบายและข้อมูล 4 ค่า ปุ่มความเร็วคุมความเร็วการหมุน ปุ่มหยุดใช้หยุดดูนิ่ง ๆ ได้

มี 9 ดวงให้เลือก ดวงอาทิตย์กับดาวเคราะห์ 8 ดวง ผิวดาวสร้างจาก canvas ในเครื่องเอง ไม่โหลดรูปจากที่ไหน แถบเมฆของพฤหัสบดีพร้อมจุดแดงใหญ่ หลุมอุกกาบาตของพุธ ขั้วน้ำแข็งของโลกกับอังคาร วงแหวนเสาร์เป็นสี่ชั้นมีช่องว่าง

ขนาดดาวในภาพถูกย่อสัดส่วนให้ดาวเล็กยังมองเห็น (พฤหัสบดีใหญ่กว่าพุธจริง ๆ ถึง 29 เท่า) มีหมายเหตุบอกไว้ในการ์ดแล้ว ส่วนตัวเลขจำนวนดวงจันทร์ใช้คำว่า "ราว" เพราะมีการค้นพบเพิ่มเรื่อย ๆ

## ปรับขนาดของที่แสดง

ในไฟล์ index.html มีค่าคงที่สองตัวอยู่ใกล้บนสุดของสคริปต์

- `SYSTEM_SIZE = 1.55` โหมดกำเนิด 1 = เท่าความกว้าง marker พอดี ค่านี้ตรึงไว้ตามหลัก AR คือถือกล้องใกล้แล้วภาพใหญ่ขึ้นจริง ถ้าอยากให้ใหญ่ขึ้นอีกเพิ่มเลขนี้ แต่เกิน 1.8 วงโคจรดาวชั้นนอกจะเริ่มล้นจอเวลาถือใกล้
- `BODY_SIZE = 0.6` โหมดดาวเคราะห์ เป็นแค่ขนาดตั้งต้น เพราะโหมดนี้มีการย่อขยายอัตโนมัติให้ดาวกว้างราว 60% ของจอเสมอ ไม่ว่าจะถือใกล้หรือไกล

เหตุที่ดาวเคยล้นจอ: จอมือถือแนวตั้งเห็นภาพจากกล้องแค่ราว 35% ในแนวนอน เพราะ AR.js ขยายภาพเป็นสัดส่วน 4:3 แล้วครอบซ้ายขวาทิ้ง ของที่กว้างเกินนั้นจึงหลุดขอบจอทั้งที่คำนวณว่าอยู่ในมุมมองกล้อง ตอนนี้โค้ดอ่านค่าจากเมทริกซ์กล้องกับความกว้าง canvas จริงมาคำนวณให้แล้ว

## UI

- แถบเวลาเป็นสเกลเดียว ขีดบอกขั้นทั้งหกวางตามเวลาจริงของแต่ละขั้น ระยะจึงไม่เท่ากัน ขีดของขั้นที่กำลังเล่นจะสูงขึ้นและเป็นสีเหลือง
- ปุ่มควบคุมเหลือสามปุ่มวงกลมกับแถบความเร็วแบบเลื่อน ทั้งหมดวางบนไล่เฉดจากขอบจอ ไม่ใช่กล่องทึบ ภาพกล้องจึงต่อเนื่องทั้งจอ
- ปุ่มรูปตามุมขวาบนคือซ่อนแผงควบคุมไว้ดูภาพเต็มจอ แตะที่ไหนก็ได้เพื่อเรียกกลับ
- ปุ่มวงกลม i ข้าง ๆ คือตัวเลขตรวจสอบ
- กรอบที่ marker เปลี่ยนเป็นมุมฉากสี่มุมแบบช่องมองภาพ
- ลูกบาศก์ทดสอบการวาดภาพถอดออกแล้ว

## ปุ่มควบคุม

- ความเร็ว 0.5× / 1× / 2× / 4× (กดตอนหยุดอยู่ จะเล่นต่อให้เลย)
- หยุดชั่วคราว / เล่นต่อ — ค้างภาพไว้อธิบายได้ หยุดนิ่งจริงทุกอย่าง
- ขั้นถัดไป — กระโดดไปต้นขั้นถัดไป
- เริ่มใหม่ — ย้อนไปเนบิวลาวินาที 0
- ดูแบบไม่ใช้ marker — โมเดลลอยหน้ากล้อง ใช้ตอนยังไม่มี marker

## 6 ขั้นตอน (เวลาที่ 1×)

| วินาที | ขั้น |
|---|---|
| 0–6 | เมฆโมเลกุลและเนบิวลา |
| 6–12 | เมฆยุบตัวด้วยแรงโน้มถ่วง หมุนเร็วขึ้นและแบนลง |
| 12–18 | เกิดจานรวมมวล ใจกลางจุดฟิวชันเป็นดวงอาทิตย์ |
| 18–26 | ฝุ่นพอกพูนเป็นดาวเคราะห์น้อยและดาวเคราะห์ |
| 26–34 | ลมสุริยะกวาดจานฝุ่น เห็นวงโคจรชัดขึ้น |
| 34+ | ระบบสุริยะปัจจุบัน โคจรต่อไปเรื่อย ๆ |

## ปรับแต่งเพิ่ม

- ขนาดโมเดล: ใส่ `scale="0.7 0.7 0.7"` ที่แท็ก `<a-marker>` (ปัจจุบันกว้างราว 2 เท่าของ marker)
- ภาพสั่น: ปรับค่า `k` ในฟังก์ชัน `tick` จาก 0.35 ลงเป็น 0.2 (ยิ่งน้อยยิ่งนิ่งแต่ตามช้า) ห้ามใช้ `smooth` ของ AR.js
- เครื่องช้า: ลด `const N = 720;` (จำนวนเม็ดฝุ่น) เหลือ 300–400
- ใช้ marker Hiro มาตรฐานแทน: เปลี่ยนเป็น `<a-marker id="marker" preset="hiro"></a-marker>`
